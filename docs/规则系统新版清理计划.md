# WinRouter 规则系统新版清理计划

## 目标

将规则系统统一为新版规则组模型：

```text
RuleGroup
  id
  name
  type
  values: []string
  action
  enabled
```

持久化格式固定使用 `rule-settings` schema v2，不再读取、写入或展示旧版单值规则格式。

## 当前残留

### 前端

- `App.vue` 仍存在旧的单值输入控件 `ruleForm.value`。
- `CustomRule` 和 `RuleForm` 仍保留可选 `value` 字段。
- 规则列表仍有 `row.rule.value` 展示逻辑。
- 表单 CSS 依赖旧 DOM 顺序和 `nth-child`，容易导致布局错位。
- 旧远程 JSON 规则迁移 UI、按钮和状态字段仍存在。
- Wails 调用仍导入 `MigrateRemoteRuleSet`、`ConfigureRemoteRuleSet` 等旧链路 API。

### Wails 绑定

- `models.ts` 已部分切换为 `values`，但需要重新确认与 Go 类型完全一致。
- `App.js`、`App.d.ts` 仍暴露旧远程规则迁移方法。

### Go 应用层

- `app.go` 仍包含 `MigrateRemoteRuleSet`。
- `app.go` 仍包含 `withRemoteRules`。
- 旧 `rulesets.Manager` 仍被初始化并维护。
- `rulesettings.Rule` 仍保留未持久化的 `Value` 兼容字段。
- `Settings.LegacyRemoteMigrated` 仍是旧迁移状态字段。

### 规则存储和测试

- `internal/rulesets` 仍使用单值 `Rule.Value`。
- `rulesettings` 测试仍有旧字段构造方式。
- 应用规则测试需要改成多值规则组测试。
- 部分文档和 schema 仍描述旧远程 JSON 规则路径。

## 实施步骤

### 阶段 0：源码和编码整理

1. 确认 `frontend/src/App.vue` 为 UTF-8 编码。
2. 保留当前用户界面文案，不做无关翻译重写。
3. 重新检查 Vue 模板结构，确保清理可以使用稳定补丁定位。

验收：`vue-tsc --noEmit` 能够独立运行。

### 阶段 1：前端规则组表单

1. 删除旧单值 `input v-model="ruleForm.value"`。
2. 删除 `RuleForm.value` 和 `CustomRule.value`。
3. 仅保留多行 `valuesText` 编辑控件。
4. 提交时统一执行：去空、去重、规范化、至少一个值校验。
5. 规则列表改为展示匹配值数量和多值摘要。
6. 给表单字段增加语义 class，删除依赖 `nth-child` 的布局规则。
7. 重新设计两列布局：
   - 左列：名称、匹配类型、目标、启用状态；
   - 右列：多行匹配值；
   - 操作按钮独占底部。
8. 确认窄屏自动变为单列。

验收：界面不再出现第二个“匹配值”，不会出现字段重叠或复选框放大。

### 阶段 2：前端删除旧远程规则入口

1. 删除旧远程 JSON 规则配置和迁移区域。
2. 删除 `MigrateRemoteRuleSet`、`ConfigureRemoteRuleSet`、`RefreshRemoteRuleSet` 的前端调用。
3. 删除 `legacyRemoteMigrated` 状态和相关初始化/保存逻辑。
4. 保留 SRS 来源配置、下载、校验、缓存和启停控制。
5. 规则排序仅允许用户规则组和 SRS 条目。

验收：规则页面只存在新版规则组和 SRS 两类来源。

### 阶段 3：Wails 绑定同步

1. 删除 `App.d.ts`、`App.js` 中旧远程规则 API。
2. 确认 `models.ts` 的 `rulesettings.Rule` 只包含 `values`。
3. 确认 `Settings` 不再暴露 `legacy_remote_migrated`。
4. 重新生成 Wails 绑定；若环境不支持生成，则手工同步并以 Go 类型为准。

验收：前端类型检查无旧字段和旧 API 引用。

### 阶段 4：Go 规则设置模型

1. 从 `rulesettings.Rule` 删除 `Value` 字段。
2. 删除 `LegacyRemoteMigrated` 字段。
3. 删除 `MigrateLegacyRemote` 方法。
4. `Validate` 只接受 `Values`，并校验空值、重复值和冲突动作。
5. 保持 schema v2 严格拒绝旧 `value` 字段。
6. 更新 clone、规范化和持久化逻辑。

验收：旧格式文件启动时明确报错；新版规则组可正常读取和保存。

### 阶段 5：Go 应用层和旧规则管理器

1. 删除 `MigrateRemoteRuleSet`。
2. 删除 `withRemoteRules`。
3. 删除所有旧远程规则注入调用。
4. 删除 `rulesets.Manager` 的初始化、字段和错误状态。
5. 删除 `ConfigureRemoteRuleSet`、`RefreshRemoteRuleSet`、`GetRemoteRuleSet` 等旧 API。
6. 删除 `internal/rulesets`，或明确改成不参与运行时的独立迁移工具；本次目标为删除。
7. 保留 `internal/srssets` 作为唯一远程规则来源。

验收：运行配置只来自规则设置 v2、SRS 和系统内置策略。

### 阶段 6：配置生成和语义校验

1. 确认规则组多值展开后每个值都进入统一排序区域。
2. 确认 `domain-suffix`、`domain`、`ip`、进程类型都能正确生成。
3. 确认同一组的多个值保持同一动作和顺序。
4. 确认 `final` 的现有语义按当前迁移策略处理；新版 UI 不再新增 `final`。
5. 更新规则预览，显示规则组名称、值数量和实际展开结果。

### 阶段 7：测试和验收

后端：

- `go test ./...`
- v2 多值规则读写测试。
- 旧 `value` 字段拒绝测试。
- 规则组去重和动作冲突测试。
- 多值展开和规则顺序测试。
- SRS 下载、校验、缓存和失败保留测试。

前端：

- `npm run build`
- 规则新增、编辑、删除、启停。
- 多行值保存和重新加载。
- 域名后缀、精确域名、CIDR、进程名称、进程路径。
- SRS 配置、更新、启停、排序。
- 窄屏布局检查。

## 最终验收标准

- 代码中不再出现 `managed-by-values`。
- 规则设置持久化 JSON 中不再出现 `value`。
- 前端模板中不再存在旧单值规则输入。
- 前端和后端不再暴露旧远程 JSON 迁移 API。
- `internal/rulesets` 不再参与编译或运行时规则生成。
- `go test ./...` 通过。
- `npm run build` 通过。
- 规则页面截图中每条规则组只有一个多值输入区域，字段不重叠。
