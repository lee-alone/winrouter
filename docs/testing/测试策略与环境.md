# WinRouter 测试策略与环境

## 1. 范围与退出规则

本文适用于 Phase 0 网络可行性原型、Phase 1 `direct-split` MVP 和 Phase 2 稳定性/桌面体验。验证分为四层：纯函数单元测试、锁定核心配置检查、管理员 TUN 主动探测、Windows 故障注入与物理接口抓包。任务只有在验证记录包含明确结果和原始证据路径后才可完成。

独立开发阶段由开发者执行代码、网络和测试三职责自审。阻断级缺陷必须关闭；严重级缺陷必须关闭或有明确降级策略；一般兼容性问题可作为风险进入下一阶段。第二套 Windows 环境因当前不可用，按用户确认改为发布前补测项，不伪造覆盖结果。

## 3. 工具与证据

- `go test -count=1 ./...`：模型、接口匹配、拓扑、配置生成、地址池与持久化。
- `go vet ./...`：Go 静态检查。
- sing-box `check`：版本、SHA-256、JSON 语法和核心语义检查。
- `pktmon`：物理 NIC、源地址、目标和协议交叉确认。
- Windows IP Helper、CIM、NetAdapter：接口、地址、路由和驱动证据。
- 故障注入：强杀父进程、强杀核心、物理接口断开/恢复、S0 待机、休眠/唤醒、注销/重启、迁移失败和默认路由归属变化。
- 原始输出按阶段保存在 `build/phase0/`、`build/phase1*`、`build/phase2-*`；结论分别汇总到对应 `phase-N-验证记录.md`。

## 4. 受控目标

当前两张网卡均可完整访问互联网，A/B 只表示出口标签，不宣称国内/全球能力。TCP 使用 `1.1.1.1:443`、`8.8.8.8:443`；UDP 使用 Cloudflare NTP；DNS 使用 Cloudflare、Google 的 UDP/DoT/DoH；代理使用受控 HTTP CONNECT 节点。

## 5. 缺陷等级

- 阻断：错误接口泄漏、无限递归、无法清理网络资源、核心失控。
- 严重：主要协议不可用、恢复超 30 秒、错误规则静默生效。
- 一般：单个公共上游延迟或重试、诊断信息不足但存在可靠替代证据。
- 轻微：不影响行为的日志、文本或工具易用性问题。

缺陷修复必须补回归断言或可复现实验。配置和实验器变化同步更新验证记录。

## 6. 追踪

`P0-IF` 对应 `internal/interfaces`；`P0-TUN` 对应 `internal/config`、`internal/tunprefix`、`internal/core`；`P0-DNS/IPV6/PROXY` 对应强类型生成器和相应实验输出；`P0-LIFE` 对应 Job Object、正常停止、网络变化/睡眠监测及 `build/run-*-elevated.ps1`。

Phase 1 的 `P1-IF/CFG/CORE/UI/OBS` 分别对应 `internal/interfacemanager`、
`internal/config` 与 `internal/policy`、`internal/core` 与 `internal/helperipc`、
`frontend/src`、`internal/observability`。退出用例 `P1-EXIT-T01..T09` 对应
`docs/testing/phase-1-验证记录.md` 中的命令和 `build/phase1*` 证据目录。

Phase 2 的 `P2-STAB` 对应 `internal/recovery`、`internal/interfacemanager`、
`internal/autostart` 及真实休眠、注销、重启和双默认路由实验；`P2-UX` 对应
Wails 后端、`frontend/src` 和当前用户启动项。Hyper-V、WSL、Docker 与常见 VPN
组合由具备相应环境的用户执行，回传脱敏诊断包后按真实缺陷定向调试，不计作当前
单机环境已覆盖。
