# 远程状态与企业策略安全评估

> 评估日期：2026-08-01  
> 关联任务：P4-EXT-04、P4-EXT-05  
> 结论：安全模型已确定；当前版本不开放远程状态查看或企业策略下发

## 1. 当前安全基线

生产应用没有 TCP/HTTP/WebSocket 管理监听端口。UI 以普通用户权限运行，提权 helper 仅通过按当前用户 SID
命名的本机 Named Pipe 接受请求；Pipe DACL 限制当前用户、管理员和 SYSTEM，并使用每次 helper 会话生成的
随机令牌认证。helper 的 RPC 方法是固定枚举，不接受任意命令、可执行文件或路径。

诊断数据可能包含接口名称、地址、网关、核心错误、探测目标、进程规则状态和流量计数。即使不包含密码，这些
数据也足以描述设备网络拓扑和使用行为，不能直接复用现有 `GetObservations` 或诊断包作为远程响应。

本次代码面检查未发现 TCP/HTTP 远程管理 listener 或启动路径；现有 `StartMockHTTPProxy` 是未被应用入口调用的
受控 CONNECT 实验工具，不提供状态或控制 API。生产控制入口仅为 Named Pipe。当前版本没有租户、设备注册、
远程身份、证书轮换、撤销、审计服务或策略信任锚，因此不存在可安全启用远程能力的完整信任生命周期。

## 2. 只读远程状态查看

### 2.1 威胁与资产

需要防御未授权查看、设备枚举、中间人、重放、令牌泄漏、恶意服务端扩大查询范围、请求洪泛，以及未来把只读
通道误扩展为控制通道。受保护资产包括接口标识和地址、节点与订阅信息、进程/域名规则、探测目标、日志、凭据、
流量使用模式，以及本机 helper 的控制能力。

### 2.2 允许的未来架构

1. 默认关闭，由本机交互用户明确配对；不随安装或登录自动注册。
2. 普通权限的独立状态代理主动建立出站 TLS 1.3 连接，不增加入站监听，不由 helper 或 sing-box 联网。
3. 每台设备使用独立非导出私钥和短期客户端证书；私钥由 Windows CNG/DPAPI 保护。配对必须显示服务身份、
   数据范围和一次性确认码。服务端身份固定到受控 CA，禁止忽略证书错误。
4. 远程协议只提供版本化的 `StatusSnapshot`，不存在通用方法名、脚本、路径、配置、启动、停止或刷新字段。
5. 设备端按固定周期推送状态投影；服务端不能临时请求新增字段。限制频率、响应大小、会话时长和并发。
6. 本机保留配对、读取、撤销和认证失败审计；用户可立即撤销设备证书并删除本地身份。

### 2.3 最小状态投影

允许：应用版本、核心状态、恢复状态、A/B 是否可用、最近一次健康检查是否成功、按 MiB 取整的 A/B 聚合流量、
流量预算比例区间，以及 UTC 采样时间。

禁止：IP、MAC、GUID/LUID、网关、DNS、接口完整名称、进程路径、域名/IP 规则、节点地址、订阅来源、探测目标、
原始日志、关联 ID、核心 PID、配置正文、rule-set 正文或哈希、密码、令牌、API secret。显示名称只能使用用户为
远程查看单独设置的别名，不上传 Windows 友好名称。

### 2.4 安全门槛与当前决策

开放前必须完成设备注册/撤销、证书轮换、服务端租户隔离、速率限制、审计留存、隐私说明、字段级测试、代理服务
安全评审和端到端渗透测试。远程状态服务故障不得影响本机分流；缓存不得包含超出投影的数据。

当前缺少上述控制面和运营基础设施。决定维持关闭，不增加监听端口、状态代理、配对入口或远程 API。该结论完成
P4-EXT-04 的“评估”范围，但不等于功能发布批准。

## 3. 签名企业策略

### 3.1 威胁与资产

需要防御伪造策略、签名替换、旧策略回滚、跨租户重放、过期策略、密钥泄漏、解析差异、部分应用、危险字段注入、
管理员失去恢复能力，以及远程策略借 helper 获得任意执行。企业策略可以改变流量去向，其完整性要求高于普通配置。

### 3.2 建议的签名封装

未来格式必须使用新的独立 Schema，不复用订阅或 rule-set 文档。封装只包含严格字段：`schema_version`、`key_id`、
`algorithm`、`payload` 和 `signature`。`algorithm` 首版唯一允许 Ed25519；`payload` 为原始 UTF-8 JSON 字节的 Base64，
签名覆盖固定域分隔符 `WinRouter Enterprise Policy v1` 与原始 payload 字节，避免不同 JSON 序列化产生歧义。

payload 必须严格解码并拒绝未知字段，至少包含租户 ID、策略 ID、单调递增 revision、签发/生效/过期时间、目标应用
版本范围和策略内容。信任锚只能由本机管理员通过受保护安装/注册流程预置；payload、下载响应和普通用户配置不能
添加或替换信任锚。信任锚记录 key ID、租户、有效期、用途和撤销状态。

### 3.3 策略范围与应用语义

首版只允许已建模的模式约束、自定义规则、远程 rule-set 固定来源/哈希和功能禁用项。禁止携带代理/订阅凭据、
任意文件、命令、可执行路径、helper 方法、诊断上传地址或新的信任锚。进程完整路径规则需单独管理员授权，不能
通过宽泛路径或通配符扩展。

应用顺序固定为：验证签名和租户、检查时间与 revision、防回滚、严格 Schema/模型验证、生成完整候选配置、执行
现有四层校验、原子提交、健康检查、失败回滚。helper 只接收通过普通应用生成的完整受限配置，不解析签名、不联网。
策略优先级必须在新配置 Schema 中显式版本化并在 UI 展示，不能暗中改变当前用户规则顺序。

设备必须持久化每个策略的最高已接受 revision，并对状态文件实施仅管理员可写 ACL；过期、撤销、降级、租户不符、
未知 key、未知字段或任何校验失败均拒绝新策略并继续使用最后有效配置。紧急恢复通过本机管理员移除注册和信任锚，
不是远程“绕过签名”命令。

### 3.4 分发与密钥生命周期

签名允许使用不可信缓存传输，但下载仍要求 HTTPS、大小限制、超时、禁止跨源重定向和原子暂存。签名私钥不得存在
客户端或分发服务；应由独立签名系统/HSM 保管。必须定义生成、双人审批、轮换、交叉签名、撤销、租户迁移、时钟
异常、离线设备和泄漏响应流程，并记录不含策略敏感正文的审计事件。

### 3.5 当前决策

当前没有管理员注册、受保护信任锚、防回滚状态、密钥轮换/撤销、策略冲突 UI、签名服务或运营审计。决定不开放
策略 URL、上传入口、后台轮询或远程下发 RPC。完成这些前置能力及独立安全评审后，方可建立新的实施任务；不能将
现有远程 rule-set 的单文件 SHA-256 校验宣称为企业策略签名。该结论完成 P4-EXT-05 的“评估”范围。
