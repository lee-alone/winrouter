# Windows 双网卡智能分流软件设计白皮书

> 项目代号：WinRouter / DualRoute  
> 文档版本：v0.2  
> 日期：2026-07-31  
> 目标平台：Windows 10 / 11 x64  
> 技术栈：Go 1.22+、Wails、Vue 3 + TypeScript、sing-box 1.13+

## 1. 文档目的

本文定义 Windows 双网卡智能分流软件的产品范围、系统架构、流量与 DNS 策略、安全边界、生命周期、测试方法和阶段计划，作为开发、测试和发布的共同技术基线。

所有 sing-box 配置在实现时以项目锁定版本的官方配置格式为准，并必须通过对应版本的 `sing-box check` 校验。本白皮书中的配置片段只表达设计意图，不作为可直接运行的最终配置。

## 2. 背景与目标

### 2.1 使用场景

用户同时拥有两块物理网卡：

- 网卡 A：国内出口，费用低或免费，但只能稳定访问国内网络。
- 网卡 B：全球出口，可以访问完整互联网，但流量成本较高。

系统需要自动选择出口：

- 国内公网地址和国内域名通过网卡 A。
- 非国内流量通过网卡 B，或通过绑定在网卡 B 上的代理节点。
- 本机、局域网、网关、虚拟网络等地址根据其实际所属接口访问，不能简单归入国内出口。
- DNS 查询必须与业务流量使用一致的出口策略，避免污染、泄漏和路由环路。

### 2.2 产品目标

1. 提供清晰、可诊断的 Windows 桌面客户端。
2. 使用成熟内核实现 TUN 捕获、规则匹配和出口绑定。
3. 支持双网卡直连和双网卡代理两种主要模式。
4. 尽量减少应用自行维护的永久系统路由。
5. 在程序退出、崩溃、休眠恢复和网卡变化后可恢复到确定状态。
6. 为订阅、进程分流、测速等后续能力保留扩展空间。

### 2.3 当前非目标

- macOS 和 Linux 支持。
- 自研内核驱动或 TUN 实现。
- 账号、计费、广告和云端策略系统。
- 在 MVP 中支持所有代理协议和订阅格式。
- 将本产品作为局域网网关供其他设备使用。

## 3. 核心设计原则

### 3.1 配置驱动

分流规则由结构化模型生成 sing-box JSON。禁止通过字符串拼接配置。每次应用新配置前必须完成语义校验和内核校验。

### 3.2 最小权限

Wails UI 以普通用户权限运行。需要创建 TUN、控制核心或调整临时路由的操作由提权 helper 执行。UI 不长期持有管理员权限。

### 3.3 明确出口

业务连接、DNS 查询和代理服务器连接均明确绑定出口接口。不得依赖 Windows 当前默认路由隐式选择网卡。

### 3.4 可回滚

配置更新采用“校验、替换、重启、健康检查、失败回滚”的事务式流程。系统任何时刻都应能回到上一个已知可用配置或完全停用状态。

### 3.5 可观测和可验证

界面展示的是经过核心 API、接口计数器和健康检查验证的状态，而不是仅展示用户选择。每次路由决策应能通过日志说明命中的规则和出口。

## 4. 总体架构

```text
+---------------- Wails UI（普通权限） ----------------+
| 页面、状态管理、用户配置、日志与诊断展示             |
+-------------------------+----------------------------+
                          | Wails bindings
+-------------------------v----------------------------+
| Go Application Backend                               |
| InterfaceManager | PolicyEngine | ConfigGenerator    |
| CoreController   | RuleManager  | StatsMonitor       |
+-------------------------+----------------------------+
                          | 受限 Named Pipe RPC
+-------------------------v----------------------------+
| Elevated Helper / Windows Service                    |
| 核心进程控制、TUN 生命周期、权限操作、状态恢复        |
+-------------------------+----------------------------+
                          | 配置文件、进程、控制 API
+-------------------------v----------------------------+
| sing-box Core                                         |
| TUN | DNS | Route Rules | Direct/Proxy Outbounds     |
+--------------------+-------------------+--------------+
                     |                   |
                 网卡 A              网卡 B
                国内出口             全球出口
```

### 4.1 组件职责

#### InterfaceManager

- 枚举物理和虚拟接口、地址、前缀、网关、DNS、状态与成本。
- 使用 Windows Interface GUID 作为主持久标识；MAC、当前 IPv4 前缀和友好名称仅作为辅助校验信息。
- 接口禁用、驱动重装或硬件变化后若主标识失效，只向用户展示可能的匹配候选；无法唯一确认时强制重新选择，不静默猜测。
- 监听接口增加、删除、断开、地址变化和默认路由变化。
- 识别回环、TUN、Hyper-V、WSL、VPN、Docker 等非候选接口。
- 构建本机及各接口直连网络前缀集合。
- 检查候选 TUN 前缀是否与本机接口地址及路由表重叠，并从预定义前缀池确定性选择可用前缀。

#### PolicyEngine

- 将用户选择、接口拓扑、内置规则和自定义规则合并为统一策略。
- 计算规则优先级，检测冲突、不可达出口和潜在环路。
- 决定局域网、国内公网、国外公网、DNS 和代理服务器的出口。
- 输出有序规则列表；其顺序必须与最终 JSON 中 `route.rules` 的顺序严格一致。

#### ConfigGenerator

- 使用项目维护、与锁定 sing-box 版本对应的最小强类型 Go 模型，并只通过 Go 标准库序列化生成 JSON。
- 默认不直接依赖 sing-box 内部 Go option 包，避免内部 API 强耦合及链接层面的许可证边界变化。
- 生成 TUN、DNS、route、rule-set、direct 和 proxy outbounds。
- 不将密钥写入日志，并支持生成脱敏配置。
- 依次执行模型校验、JSON Schema 校验、语义校验和锁定版本的 `sing-box check`。

#### CoreController

- 通过 helper 启动、停止和重启 sing-box。
- 维护当前配置、上一个可用配置和运行状态。
- 执行健康检查、退避重启和故障回滚。
- 采集标准输出、标准错误和核心控制 API 状态。

#### RuleManager

- 管理内置 rule-set、版本、哈希和本地缓存。
- 更新失败时继续使用最后一个已验证版本。
- 后续支持用户规则、订阅和规则优先级编辑。

#### StatsMonitor

- 从核心 API 获取连接与流量状态。
- 以绑定接口的 TCP、UDP 和 DNS 主动探测作为出口健康判定依据。
- Windows 接口计数器存在延迟且包含其他进程流量，仅用于趋势展示和辅助诊断，不单独作为健康判定依据。
- 对核心状态、进程状态、主动探测结果和接口计数器进行交叉观察。

## 5. 流量分类与优先级

规则从上到下匹配，第一条命中后停止。建议优先级如下：

PolicyEngine 输出的有序规则列表必须原样映射到 sing-box `route.rules` 数组。单元测试既要断言策略层顺序，也要反序列化最终 JSON 并断言实际规则顺序，防止生成阶段重排规则。

| 优先级 | 流量类型 | 处理方式 |
|---:|---|---|
| 1 | 回环、本机服务、核心控制 API | 直接本地访问，不进入外部出口 |
| 2 | TUN 自身、DNS 上游、代理服务器地址 | 按专用规则绑定接口，防止环路 |
| 3 | 用户明确指定的规则 | 使用用户选择的出口或拒绝 |
| 4 | 接口直连网络、网关和链路本地地址 | 按目标所属接口直连 |
| 5 | 保留地址和不应进入公网的地址 | 直连、拒绝或明确提示 |
| 6 | 国内域名和国内公网地址 | 网卡 A |
| 7 | 其他流量 | 网卡 B 或绑定网卡 B 的代理 |

用户规则内部先匹配进程名称/完整路径，再匹配域名/IP，组内保持用户顺序。名称规则跨进程重启保持稳定；
发现同名程序来自多个路径时拒绝应用并要求完整路径。子进程不隐式继承父进程规则，实际联网的子进程必须
显式配置。路径变化、目标未运行或权限不足必须在规则状态中明确展示，不得自动降级为更宽泛的名称规则；
未命中进程覆盖时仍进入既有域名/IP与最终出口策略，不绕过基础分流。

### 5.1 内网地址分流

不得使用“所有 RFC1918 私有地址都走网卡 A”的固定规则。私有地址可能属于网卡 B、VPN、Hyper-V、WSL 或其他虚拟网络，错误绑定会导致局域网设备不可达。

启动和接口变化时，InterfaceManager 根据 Windows 接口表生成直连前缀，例如：

```text
网卡 A：192.168.10.23/24，网关 192.168.10.1
网卡 B：10.20.30.8/24，网关 10.20.30.1
Hyper-V：172.24.0.1/20
```

相应策略为：

- `192.168.10.0/24` 通过网卡 A 直连。
- `10.20.30.0/24` 通过网卡 B 直连。
- `172.24.0.0/20` 通过对应 Hyper-V 接口访问或绕过 TUN。
- 其他未知私有前缀不默认归入国内出口；按安全策略直连默认接口、拒绝或提示用户。

如果相同前缀同时出现在多个接口，应按 Windows 路由度量、接口状态和用户覆盖规则解析；无法唯一确定时不得静默选择。

### 5.2 TUN 地址段分配

- 启动预检必须同时检查本机现有接口地址和完整路由表，确认候选 TUN 前缀不存在重叠。
- 候选前缀从项目维护的私有地址池中确定性选择；选中结果随配置持久化，避免无故变化。
- 每次启动、休眠恢复及网络拓扑变化后重新验证。发生冲突时选择下一个可用前缀并重新生成配置。
- 若地址池没有可用前缀，则中止启动并向用户展示冲突项，不允许带冲突继续运行。

### 5.3 代理模式防环路

- 代理服务器域名必须先通过指定 DNS 解析。
- 解析得到的代理服务器 IP 必须绑定网卡 B。
- 代理服务器连接不得再次命中代理 outbound。
- 服务器 IP 变化时更新专用规则，并在切换前完成可达性检查。
- 多级代理必须显式描述 detour 链，不依赖默认出口。

### 5.4 IPv6 策略

IPv6 采用显式、可持久化策略，默认 `block`，不允许 IPv6 无意绕过 TUN：

- `block` 时拒绝 AAAA 查询及 TUN 中的 IPv6 流量；IPv6 前缀重叠不影响 IPv4 双出口预检。
- `split` 仅在两个出口均具备可用 IPv6 地址、IPv6 默认路由且不存在跨出口 IPv6 前缀重叠时允许启动；该模式保留 AAAA 并为 IPv6 使用与 IPv4 等价的分类和 DNS 策略。
- MVP 若选择阻止 IPv6，UI 和结构化日志必须明确显示“IPv6 已按策略阻止”，不得显示为未知或故障状态。
- 切换策略必须在核心停止时完成，并重新执行预检；不得以系统默认行为代替用户策略。

## 6. DNS 架构

DNS 是 MVP 的组成部分，而不是体验增强项。

### 6.1 目标

- 国内域名优先使用绑定网卡 A 的国内 DNS。
- 其他域名使用绑定网卡 B 的可信 DNS，或通过代理查询。
- DNS 上游连接必须显式绑定对应接口。
- 避免 DNS 污染、泄漏、错误缓存和查询环路。

### 6.2 处理流程

1. TUN 捕获系统 DNS 请求。
2. DNS 规则先处理本地域名和特殊用途域名。
3. 国内域名规则选择国内 DNS；其他域名选择全球 DNS。
4. DNS 返回地址参与后续路由判定，必要时由域名规则覆盖 IP 归属结果。
5. 缓存键至少区分查询名、类型和所用上游策略。

### 6.3 必须明确的实现项

- 最终实现选择真实 IP 或 fake-IP 模式，并记录兼容性结论。
- 国内和全球 DNS 上游不得共享未经区分的缓存结果。
- DoH/DoT 的引导地址和服务器连接必须有防环路规则。
- 处理 Windows 多接口 DNS、NRPT、VPN DNS 和休眠恢复后的变化。
- 日志记录所选 DNS 策略，但不记录敏感完整查询历史，除非用户开启调试模式。

## 7. 运行模式

运行模式在 UI、持久配置和 ConfigGenerator 中使用同一个枚举。产品模型定义下列两个互斥值：

| 枚举值 | 国内流量 | 其他公网流量 | `route.final` 意图 |
|---|---|---|---|
| `direct-split` | 网卡 A 直连 | 网卡 B 直连 | `foreign-direct` |
| `proxy-split` | 网卡 A 直连 | 代理，代理出口强制绑定网卡 B | `proxy` |

Phase 1 只开放 `direct-split`；Phase 3 完成代理能力后开放 `proxy-split`。未开放的枚举值必须被配置校验拒绝。`hybrid` 作为更后期的预留模式，由规则集决定流量通过网卡 B 直连还是代理；当前版本不接受或生成该枚举值。ConfigGenerator 必须根据模式唯一确定最终 outbound，不能根据节点是否存在等隐式状态改变 `route.final`。

### 7.1 双网卡直连（`direct-split`）

- 国内公网和国内域名通过网卡 A。
- 其他公网流量通过网卡 B。
- 局域网流量按照目标所属接口直连。

### 7.2 双网卡代理（`proxy-split`）

- 国内流量通过网卡 A。
- 其他公网流量进入代理 outbound，不允许自动回退为网卡 B 直连。
- 代理服务器及其 DNS 查询强制通过网卡 B。

### 7.3 单网卡降级

当一块网卡不可用时，默认暂停受影响的出口，防止产生意外费用或流量泄漏。用户可事先选择以下降级策略之一：

- 严格：受影响流量失败，不自动改走另一网卡。
- 可用性优先：显示明确警告后临时使用可用网卡。
- 关闭分流：停止 TUN 并恢复系统网络。

默认使用严格策略。

## 8. 配置应用与生命周期

### 8.1 启动流程

1. 枚举接口并解析已保存的 LUID/GUID。
2. 检查接口状态、地址、网关、前缀冲突和管理员 helper。
3. 加载并验证 rule-set。
4. 生成候选配置到受限临时目录。
5. 使用锁定版本内核执行配置检查。
6. 启动核心并等待 TUN、控制 API 和出口探测全部健康。
7. 成功后将配置标记为最后一个已知可用版本。

### 8.2 配置更新

完整配置变更不依赖 Clash API 热加载。默认流程为：

```text
生成候选配置 -> 静态校验 -> sing-box check -> 原子保存
-> 停止旧核心 -> 启动新核心 -> 健康检查
-> 成功提交 / 失败恢复旧配置
```

仅当锁定版本明确支持某项运行时操作时，才通过控制 API 修改节点选择等有限状态。

### 8.3 异常恢复

- helper 使用 Windows Job Object，并设置关闭 Job 时终止子进程。
- 核心意外退出采用有上限的指数退避，避免配置错误导致无限重启。
- UI 崩溃不应让提权组件永久失控；helper 根据心跳和预设策略停止核心或维持已确认状态。
- 系统休眠恢复、接口变化或地址变化后重新计算策略并执行健康检查。
- 启动时检查上次异常中断标记，并清理本产品创建的残留资源。
- 只清理由本产品创建且具有可验证标识的资源。

## 9. 权限与安全

### 9.1 提权边界

- UI 和常规配置管理保持普通权限。
- helper 只暴露启动、停止、校验、查询状态等结构化 RPC。
- Named Pipe 使用 ACL 限制为当前用户和管理员，并验证客户端身份。
- helper 不接受任意可执行文件、任意命令行或未经约束的文件路径。
- 核心二进制在运行前验证版本和 SHA-256。

### 9.2 密钥与配置

- 代理密码、UUID、订阅凭据使用 Windows DPAPI 保护。
- Clash API 仅监听回环地址，使用随机 secret。
- 配置文件和临时文件设置仅当前用户及 helper 可读的 ACL。
- 日志、崩溃报告和诊断包默认脱敏。
- 导出诊断包前显示将包含的信息，并允许用户预览。

### 9.3 供应链与许可证

- 固定 sing-box、前端依赖和 rule-set 版本。
- 发布包记录组件版本、哈希、来源和许可证。
- 外部进程边界不等于自动免除 GPL 义务；分发 sing-box 时仍需满足其许可证及源码提供、版权声明等要求。

### 9.4 远程能力边界

- 当前版本不提供远程管理监听端口、远程状态代理或企业策略下发入口。
- 未来只读状态查看只能由普通权限独立组件主动出站连接，使用设备独立证书和固定最小状态投影；不得复用 helper、
  诊断包或完整 `GetObservations`，也不得包含任何控制方法。
- 未来企业策略必须使用管理员预置的离线信任锚、严格版本化 Schema、签名原始载荷、租户绑定、过期检查和单调
  revision 防回滚，并沿用完整配置四层校验、原子提交和失败回滚。
- helper 不联网、不管理远程身份、不解析企业签名；远程数据不能增加 helper RPC 方法或扩大配置字段范围。
- 详细威胁模型、字段清单、信任生命周期及当前维持关闭的决策见 `docs/远程能力安全评估.md`。
- 发布包必须包含 sing-box 的许可证文本、版权声明，以及获取与所分发二进制精确对应的源码和项目补丁的明确方式；可使用有效链接或随包提供源码。
- 商业发布前进行独立许可证审查。

## 10. 用户界面

### 10.1 首次使用

首次启动流程为：

1. 检测候选网卡并展示地址、网关和连通性。
2. 选择国内出口和全球出口，不允许选择同一接口。
3. 选择直连或代理模式。
4. 展示自动识别的局域网前缀和 IPv6 状态。
5. 执行预检并启动。

### 10.2 主要页面

- 仪表盘：运行状态、模式、实际出口、速率、连接数和告警。
- 网卡：候选接口、稳定标识、地址、网关、直连前缀和实时状态。
- 规则：规则来源、优先级、命中计数和自定义覆盖。
- 代理：节点、延迟、出口绑定和服务器解析结果。
- 日志：分级过滤、关联事件和脱敏导出。
- 设置：DNS、IPv6、降级策略、日志和开机启动。

### 10.3 交互要求

- 状态必须区分“用户已选择”“核心已应用”和“出口已验证”。
- IPv6 被策略阻止时，仪表盘和日志明确显示该策略状态，不将其误报为网络故障。
- 网卡切换、模式切换和允许流量降级需要明确确认。
- 常规启动和停止不需要二次确认。
- 错误信息同时给出原因、影响和可执行的恢复操作。
- 不使用单一颜色表达关键状态，兼顾无障碍识别。

## 11. 日志、监控与诊断

### 11.1 结构化日志

日志至少包含时间、级别、组件、事件 ID、配置版本和关联 ID。关键事件包括：

- 接口解析及变化。
- 配置生成、校验、提交和回滚。
- 核心启动、退出及重启。
- DNS 上游选择和失败类型。
- 路由规则命中摘要和出口健康状态。

### 11.2 健康检查

- 核心进程存活。
- 控制 API 可访问且鉴权正常。
- TUN 接口存在且地址正确。
- 国内探测目标实际通过网卡 A。
- 全球探测目标实际通过网卡 B 或代理。
- 两组 DNS 上游均通过预期接口访问。

出口判定以主动探测为主。探测至少覆盖绑定接口的 TCP、UDP 和 DNS，并记录本地源地址、目标、协议、预期接口、实际接口、耗时和结果。接口计数器只用于辅助观察，不能因其他进程流量或计数延迟单独触发出口故障。

探测应限制频率和流量，不依赖单一商业网站。

### 11.3 诊断包

诊断包包含：

- 脱敏后的应用配置和内核配置。
- 应用与核心日志。
- 接口、地址、路由和 DNS 摘要。
- 核心、规则集和应用版本。
- rule-set 的版本、SHA-256、脱敏后的来源 URL、规则条数、文件大小、最后成功加载时间和校验结果。
- 最近的健康检查结果。

诊断包默认不包含完整 rule-set 二进制。不得包含明文密码、UUID、订阅凭据、API secret、来源 URL 中的 token 或签名参数，以及完整浏览历史。

## 13. 测试策略

### 13.1 单元测试

- 接口前缀计算和冲突解析。
- 规则优先级及国内/国外分类。
- IPv4、IPv6、保留地址和重叠网段处理。
- 配置生成、脱敏和版本迁移。
- 重启退避和状态机。

### 13.2 集成测试

- 验证普通 UI 无法越过 helper RPC 权限边界。

## 14. MVP 验收标准

MVP 只有在以下条件全部满足时才可发布：

1. 用户可通过 Interface GUID 选择两块不同网卡；主标识失效且无法唯一匹配时必须重新选择。
2. 国内测试流量通过主动探测并辅以抓包确认经过网卡 A。
3. 国外测试流量通过主动探测并辅以抓包确认经过网卡 B 或当前模式指定的代理。
4. 两类 DNS 查询均通过预期出口，且没有向错误接口泄漏。
5. 两块网卡所属局域网地址均可通过各自接口访问。
6. 代理模式下代理服务器连接始终通过网卡 B，且不存在环路。
7. TCP、UDP、IPv4 均完成验证；若启用 IPv6，则执行等价的 IPv6 出口测试；若阻止 IPv6，则 AAAA 解析和直接 IPv6 连接应按设计失败或被拦截，且 UI 与日志显示“IPv6 已按策略阻止”。
8. 启停循环 100 次后无残留进程、TUN 或本产品创建的路由。
9. 网卡断开、休眠恢复及核心崩溃后符合所选降级策略。
10. 连续运行 24 小时无崩溃，内存增长、CPU 和丢包满足测试计划规定的阈值。
11. 诊断包足以定位常见配置、权限、接口和出口问题，且敏感字段已脱敏。

发布前应在测试计划中填写具体性能阈值，禁止使用“无严重泄漏”或“基本正常”等不可测量描述。

## 15. 开发阶段

### Phase 0：网络可行性原型

- 无 UI 的 Go 控制程序。
- 双网卡接口绑定和 TUN 验证。
- 按接口前缀处理两个局域网。
- DNS 双出口和代理防环路验证。
- Windows 休眠、断网和清理实验。

Phase 0 必须同时满足以下退出标准：

1. 连续启停 50 次，无残留 sing-box/helper 进程、TUN 接口或本产品创建的路由。
2. 在受控测试集内，国内和国外 TCP、UDP、DNS 探测的出口选择正确率均为 100%。
3. 两块网卡的直连局域网前缀均可达，且没有误走另一出口。
4. 代理服务器连接始终通过网卡 B，不产生递归代理连接或资源异常增长。
5. 休眠恢复后 30 秒内恢复到策略一致状态；无法恢复时必须在 30 秒内进入安全停止状态并给出明确原因。
6. TUN 候选前缀与现有接口或路由冲突时能够自动选择可用前缀；地址池耗尽时安全停止。

任一硬性指标不满足，不进入 Phase 1。每项结果必须记录 Windows 版本、sing-box 版本、网络拓扑、测试次数和可复核证据。

### Phase 1：MVP

- InterfaceManager 和稳定接口标识。
- 双网卡直连模式。
- DNS 分流和明确的 IPv6 策略。
- helper、Named Pipe RPC 和核心生命周期。
- 配置检查、健康检查和回滚。
- 基础仪表盘、网卡选择、日志及诊断。

Phase 1 不以主动禁用物理网卡、断线重连、自动重建或实际休眠恢复作为发布
阻断条件；核心异常退出仍必须有界处理并清理资源。接口变化时的安全停止、
恢复重建及休眠/唤醒一致性统一在 Phase 2 稳定性工作中完成。

### Phase 2：稳定性与体验

- 托盘和开机启动。
- 接口变化自动恢复。
- 物理网卡掉线后的安全停止、重连和双出口重建。
- 休眠/唤醒后的策略一致性恢复。
- 流量与规则命中统计。
- 完整诊断包和自动修复建议。
- 更广泛的 Windows 共存测试。

### Phase 3：代理能力

- 手动添加经过筛选的代理协议。
- 节点选择、延迟测试和可用性检查。
- 代理服务器 DNS 与网卡 B 强制绑定。
- 订阅解析、安全存储和更新回滚。

### Phase 4：增强能力

- 自定义规则和远程 rule-set 更新。
- 进程分流。
- 节点测速与收藏。
- 多语言和企业策略扩展。

## 16. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 网卡名称、地址或顺序变化 | 绑定错误 | 保存 LUID/GUID，启动时重新解析并验证 |
| 私有网段重叠 | 局域网不可达或走错出口 | 按接口前缀和路由度量计算，歧义时提示用户 |
| DNS 泄漏或污染 | 规则失效、隐私风险 | DNS 纳入 TUN 策略并绑定出口，进行专项验收 |
| 代理服务器进入 TUN 环路 | 连接失败、CPU 或流量异常 | 服务器 IP 专用规则、网卡 B 绑定和环路检测 |
| Hyper-V、WSL、VPN 冲突 | TUN 启动或访问失败 | 前缀冲突检测、动态绕过和兼容性测试矩阵 |
| 提权组件被滥用 | 本地权限提升 | 最小 RPC、身份验证、ACL、路径和二进制校验 |
| 核心升级破坏配置 | 无法启动 | 锁定版本、版本化模型、`check` 和回滚 |
| 规则集更新失败或被篡改 | 分流错误 | 本地缓存、固定来源、哈希校验和原子更新 |
| 自动重启循环 | 资源消耗、体验恶化 | 有上限的指数退避并保留故障现场 |
| 许可证履行不完整 | 发布与商业风险 | 组件清单、许可证材料、源码义务和发布前审查 |
| 远程状态泄露设备网络与使用行为 | 隐私或定向攻击 | 默认关闭、主动出站、设备证书、最小状态投影、撤销与审计 |
| 企业策略伪造、重放或回滚 | 流量劫持或策略绕过 | 离线信任锚、签名原始载荷、租户绑定、过期与 revision 防回滚、原子校验 |

## 17. 待验证决策

以下事项必须通过 Phase 0 实验后固化：

- sing-box 在目标 Windows 版本上的 TUN stack 选择。
- `strict_route` 与 Hyper-V、WSL、VPN 的具体兼容行为。
- DNS 使用真实 IP 还是 fake-IP 模式。
- helper 采用按需提权进程还是 Windows Service。
- IPv6 在首个公开版本中支持分流还是明确禁用。
- 可安全使用控制 API 完成的运行时操作范围。

实验结论应记录目标系统版本、sing-box 版本、网络拓扑、复现步骤和抓包证据，不以主观体验替代。
